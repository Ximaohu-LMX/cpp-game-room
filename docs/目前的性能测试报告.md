# 目前的性能测试报告

测试日期：2026-09-26。性质：同机回环、短时循环对战基线。以下数值来自实际运行，未对未执行的负载作估算。

本次最高测试到 **500 个同时连接的 bot**，采样期间服务端连接数保持 500–500，平均 Playing 房间数 206.75。该档实际游戏循环频率 **14.86Hz**，整轮工作耗时 **P99 上界 52.33ms**，输入接收到应用前等待 **P99 上界 92.71ms**。这些数据不能证明长期稳定容量，也不能表述为“500 人持续 20Hz 对战”。

| run | bot 非预期断线增量 | 心跳超时增量 | 结算失败尝试 | 停 bot 两秒后连接/房间 |

| 03-200-bots | 0 | 0 | 0 | 0/95 |
| 04-200-bots | 0 | 0 | 0 | 0/93 |
| 05-200-bots | 0 | 0 | 0 | 0/92 |
| 06-500-bots | 0 | 0 | 0 | 0/231 |

上述错误计数对应负载采样窗口。启动监听探测和主动关闭产生的 server read error 不归入 bot 非预期断线。心跳仅统计已观察到的响应/超时；退出时未完成请求单独记 cancelled，不能静默算成功。

200 bot 三轮：实际频率 17.69–17.75Hz；整轮工作 P99 上界 26.85–29.54ms；输入等待 P99 上界 69.65–69.65ms。这是三轮观测范围，不是统计置信区间。

实测与源码能够支持的解释：

1. 连接仍可保持时，实际 tick 频率已随负载变化；源码在工作后固定 sleep 50ms，因此 50ms 配置不是稳定 20Hz 的保证。本次保留该行为。
2. 游戏回调同步执行结算；结算尝试耗时确实包含在整轮工作耗时内。本次未做 CPU/阻塞栈分析，不能据此宣称已经证明唯一瓶颈或给出优化提升幅度。
3. 所有 bot 停止后连接数归零，但两秒观察点仍有房间。断线处理只标记连接状态，[src/room/room.cpp:109](../src/room/room.cpp#L109)；本次没有改回收策略，也没有证明这些房间最终何时释放。
4. 房间数与时长受到随机移动/攻击、等待再次匹配的影响；本测试不是持续满员战斗或固定结算频率的受控负载。
5. 没有测量无埋点对照、跨机器网络、持续 30 分钟以上、1000/5000 bot、输入到状态确认的端到端时延。不能给出这些项目的结果。
